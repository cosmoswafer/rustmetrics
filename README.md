# rustmetrics

A minimalist, lightweight, zero-config metrics collection & dashboard system written in Rust — a small Prometheus + Grafana clone in one binary, built on tokio/axum/reqwest. Collects metrics and renders dashboards.

## Quick start

```sh
cargo run --release
```

The server starts on `http://127.0.0.1:9090` — open it in a browser for the dashboard.

Push some metrics (Prometheus text format):

```sh
curl -X POST --data-binary '
# TYPE cpu_usage gauge
cpu_usage{core="0"} 37.5
cpu_usage{core="1"} 42.1
' http://127.0.0.1:9090/api/push
```

Or scrape existing Prometheus-style targets instead:

```sh
rustmetrics --scrape http://localhost:9100/metrics --scrape-interval 15
```

Select `cpu_usage` (or `up` when scraping) in the dashboard sidebar to plot it.

## Monitor a llama.cpp server (TUI)

> Quick start, recipes and troubleshooting: **[LLAMACPP.md](LLAMACPP.md)**

```sh
rustmetrics llamacpp --url http://localhost:2464
```

Runs a standalone, read-only TUI that observes a `llama-server` (single
instance or router) and charts real requests, including inference started by
other clients such as OpenCode:

- **live KPI cards** — generation & prompt throughput, KV cache and context
  usage, with trends, averages, peaks and miniature history plots
- **active model & slots panels** — load state, context size and HF repo from
  `/v1/models`, plus busy/idle slots, context meters and token counters from
  `/slots?model=...`
- **filled history charts** — full-width generation and prompt throughput plus
  context charts; a compact Prometheus grid appears when `/metrics` is enabled

The TUI **never sends inference or generation requests**. Throughput comes
from `llamacpp:predicted_tokens_seconds` and
`llamacpp:prompt_tokens_seconds` when Prometheus is available. If `/metrics`
fails or is unavailable, consecutive `/slots` counters provide a passive
fallback by measuring prompt and decoded token deltas over time. Only active
or loaded models are selected automatically; `--model NAME` pins one explicitly.

| Flag | Default | Description |
| --- | --- | --- |
| `--url` | `http://127.0.0.1:8080` | llama.cpp server base URL (env `LLAMACPP_URL`) |
| `--interval` | `2` | Poll interval in seconds |
| `--no-probe` | off | Disable the optional one-shot probe used with `--once` |
| `--probe-tokens` | `16` | Tokens generated by the one-shot `--once` probe |
| `--model` | first active | Pin the model to watch |
| `--window` | `300` | Chart history window in seconds |
| `--api-key` | none | Bearer token if the server requires auth |
| `--light` | off | Start with the light color scheme |
| `--once` | off | Poll once, print a summary and exit (scripting) |

Keys: `tab` switch active model · `m` toggle metrics panel · `t` toggle
light/dark theme · `r` refresh now · `q` quit.

Probe-test a server from the CLI without a terminal:

```sh
rustmetrics llamacpp --once --url http://localhost:2464
```

### Endpoints

| Endpoint | Description |
| --- | --- |
| `GET /` | Dashboard UI |
| `POST /api/push` | Ingest metrics (Prometheus text format) |
| `GET /api/metrics` | List known metrics (JSON) |
| `GET /api/labels?metric=NAME` | Label names/values for a metric |
| `GET /api/query?metric=NAME&from=MS&to=MS&step=MS&label.KEY=VALUE` | Range query (JSON) |
| `GET /metrics` | Self-exposition (scrape rustmetrics itself) |

### Options

Data is kept in memory (24h retention) and snapshotted to `./rustmetrics-data` every 60s, so it survives restarts. Run `rustmetrics --help` for all flags: `--listen`, `--scrape`, `--scrape-interval`, `--data-dir`, `--snapshot-interval`, `--retention`, `--no-snapshot`.
